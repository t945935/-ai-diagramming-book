# 變更演練：訂單 API 顯示名稱

狀態：提出中，未批准、未套用。純教學演練，不是真實會議或已完成修改。

## 候選需求

將介面角色「訂單 API」顯示為「訂單服務 API」，不更改原生 ID、呼叫端點、查詢政策或模組邊界。是否需要改名仍待作者確認。

## 需先回答

- 是顯示名稱調整還是實際服務拆分？
- 哪份術語表將成為批准後依據？
- 是否連章節說明與提示詞一起更新？

## 已知候選影響（不是全庫掃描結果）

| 來源 | 原生 ID | 候選處理 |
| --- | --- | --- |
| D2 平台圖 | platform.orders | 改顯示標籤，保留 ID |

| Excalidraw 白板 | 無相同 API 名稱便條 | 不為同步而製造決策 |

## 批准後才執行的驗收

1. 搜尋所有相關文字，分類同義、相關但不同層次、無關的出現位置。
2. 只改批准來源，檢查 ID 與四條端點仍一致。
3. 重產受影響圖，檢查更長標籤是否溢出。
4. draw.io 真正編輯／重開，確認端點綁定仍在。
5. 更新章節、提示詞、預覽與對照指紋，保存實測結果。

本章未執行以上改名與渲染。演練單的作用是防止「全域取代就算同步」的錯誤流程。
