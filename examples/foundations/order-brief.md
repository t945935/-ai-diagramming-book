# 訂單流程需求單：填寫範例

來源：本書虛構教學案例，沿用 [第 4 章需求](../mermaid/order-flow/requirements.md)，不新增政策。

- 讀者：需要核對訂單結果的產品與工程人員（教學設定，非真實會議參與者）。
- 問題：訂單提交後有哪些出口？付款未知與明確失敗有何不同？
- 入口：提交訂單。出口：拒絕、付款前取消、已付款、明確失敗關閉、待確認交由對帳。
- 不包含：送出後取消競態、回呼、防重實作、退款、出貨及通知。
- 箭頭：處理流程，不是模組依賴或服務呼叫。
- 已知：採第 4 章 R1–R8，不改順序與未知結果政策。
- 假設：庫存預留與建單協調由下層保證，建單失敗補償另訂。
- 未知：庫存保留期限、對帳間隔、人工責任；保持待確認。
- 工具與交付：Mermaid .mmd 加 SVG／PNG，附需求對照與驗證紀錄。

| 需求位置 | 本例對照 |
| --- | --- |
| R1–R3 | 提交、驗證、預留庫存、建立待付款訂單 |
| R4–R5 | 付款送出前取消或送出付款 |
| R6–R8 | 成功、明確失敗、未知各有不同出口 |

驗收依 [原實測紀錄](../mermaid/order-flow/verification.md)，本需求單沒有重跑渲染，不聲稱新增測試。圖源見 [order-flow.mmd](../mermaid/order-flow/order-flow.mmd)。
