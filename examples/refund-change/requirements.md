# 部分退款需求單

來源：本章新增的虛構教學假設，不代表任何真實商戶的批准政策。

| ID | 規則 | 對應證據／限制 |
| --- | --- | --- |
| R1 | 僅處理已確認付款成功的訂單；本例金額為整數 TWD 元 | 流程前置、六個金額情境；不是通用貨幣模型 |
| R2 | 0 < 要求金額 <= 已付－已退－占用 | 六個情境算術斷言 |
| R3 | 檢查、建立唯一退款紀錄與占用在同一交易；同訂單序列化 | 流程與章節規格；未實測資料庫鎖 |
| R4 | 同鍵同內容回傳既有紀錄；同鍵不同內容拒絕 | Mermaid 流程；未實作 API 冪等測試 |
| R5 | 成功只結算一次，同時增加已退、解除該筆占用 | 成功快照與 PlantUML |
| R6 | 明確失敗才解除占用，不增加已退 | 失敗快照與 PlantUML |
| R7 | 未知保留占用，查原退款；人工接手不自動釋放 | 未知快照、故障注入與 PlantUML |
| R8 | 重複終態通知不重複結算；衝突結果查核 | 重複成功快照；其他衝突未實測 |
| R9 | 供應商須支援固定退款鍵冪等與結果查詢 | 本例前提，沒有真實供應商驗證 |
| R10 | 不新增服務／模組邊界，不修改原付款圖 | 影響表與原圖指紋比對 |

新請求與退款結果處理的交易原子性、唯一性及工作送出恢復機制，是未實作的必要條件。不能從图中有「鎖定」兩字推定併發安全。

本次排除：多幣別、小數與手續費、物流退貨、稅務、爭議款、客服 UI、具體人工時限、真實回呼驗證、資料庫及支付服務整合。真實系統必須另外制定相關規格。
