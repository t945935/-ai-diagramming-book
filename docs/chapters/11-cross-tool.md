# 第 11 章：跨工具協作與轉換限制

> 樣章草稿。沿用本書虛構平台，對照既有原始檔；不假設六張圖描述相同層次，也不宣稱格式間可無損互轉。

## 11.1 共用需求，不共用所有畫法

同一項需求可以需要多張圖，但不表示每張圖都要有同一批節點。Mermaid 描述訂單步驟，D2 描述服務與邊界，PlantUML 描述參與者、訊息及狀態；Graphviz 本例描述模組依賴，draw.io 提供可拖曳的呼叫視圖，Excalidraw 留住尚未決定的問題。

跨工具協作的目標，是不讓同一條已確認規則在不同視圖互相矛盾，而不是讓所有圖片長得一樣。

本章提供 [概念對照與原始檔指紋](../../examples/cross-tool/concept-map.json)、[權威來源表](../../examples/cross-tool/authority.md)、[變更演練單](../../examples/cross-tool/change-drill.md)，以及一個真實執行的 D2／draw.io 呼叫端點契約測試。

## 11.2 名字相同，不代表物件相同

先看實際來源中的識別碼：

| 概念 | D2 | PlantUML 時序圖 | draw.io | Graphviz |
| --- | --- | --- | --- | --- |
| 訂單 API 角色 | platform.orders | API | orders | orders 是訂單模組，只是相關概念 |
| 外部支付服務角色 | external.payment | PSP | payment | 未提供對應的外部服務節點 |
| 內部付款模組 | 未展開 | 未展開 | 未展開 | payment |

Graphviz 的 `payment` 標籤是「付款模組」，並依賴 `payment_sdk`。D2 的 `external.payment` 位於「外部服務」容器，PlantUML 的 `PSP` 是付款請求對象。兩者都談付款，卻分別是模組層與服務互動層；不得只用 payment 字串建立一對一轉換。

同樣地，Mermaid 的 `reconcile` 是「標記待確認：保留庫存並交由對帳」動作，PlantUML 的 `Unknown` 是狀態，Excalidraw 的便條是討論前提。它們可以共同支持「未知不等於失敗」，但不應被合併成同一種節點。

[concept-map.json](../../examples/cross-tool/concept-map.json) 因此同時記錄概念、來源、原生 ID、來源文字與適用範圍。它是手工判定後的對照，不是自動推出的架構真相。此次十個來源引用已與原檔比對，詳見 [檢查結果](../../examples/cross-tool/mapping-verification.json)。

## 11.3 共用的是契約，不是完整檔案

D2 與 draw.io 目前有一個可共享的小契約：

```text
browser → web
web → order_api
order_api → external_payment
order_api → order_store
```

這四條是呼叫端點，不是時間順序，也不是 Graphviz 模組依賴。D2 的 `platform.web` 與 draw.io 的 `web` 可在此契約中映射為 `web`，但不要求兩者採相同原生 ID。

契約測試讀取真實 D2 來源與 draw.io XML，將端點映射後，各自與這四條比對；也檢查邊數與 draw.io 端點是否存在。只比兩張圖彼此相等仍不夠，因為兩張可能同時漏掉同一條邊。

```sh
python3 -m unittest discover -s tests -p 'test_cross_tool_contract.py' -v
```

本次在暫存副本中只刪掉 D2 的 `platform.orders -> platform.db`，測試確實失敗：`3 != 4 : D2 edge count differs`。換回原始來源，測試通過。原圖沒有被改動，也沒有替讀者刪掉資料庫關係。

這個測試刻意很小：只支援本例單行 `a -> b: label` 連線，遇到不支援的含箭頭語法會報錯。它不是完整 D2 parser，不理解容器、樣式、箭頭外觀或所有語意。

例如 D2 第一條標籤是「開啟頁面」，draw.io 第一條標籤是「HTTPS」。兩者端點相符，但一個描述動作、一個描述協定；本次沒有把標籤列入相等契約。若交付要求標籤也統一，需另訂詞彙規則，不能將這個測試說成全面一致性檢查。

## 11.4 哪一份可以改，哪一份只是產物

建立權威來源時，先分開三層：

1. 需求層：已確認的規則與明示的教學假設。尚未決定的事不能由任何一張圖自行升格成正式政策。
2. 視圖層：`.mmd`、`.d2`、`.puml`、`.drawio`、`.excalidraw`，或 Graphviz 的 JSON 與產圖程式。各視圖對自己的表示與版面負責，不取代需求。
3. 產物層：生成 DOT、SVG、PNG。用於預覽或下游消費，原則上從來源重新生成，不在此層偷偷改業務規則。

Graphviz 是特別容易混淆的一例：DOT 通常可以是原始檔，但本書第 7 章的 DOT 是由 `dependencies.json` 與 Python 程式生成，因此此案例的權威是 JSON 加程式。不能因副檔名是 DOT 就一律視為最上游。

draw.io 的人工位置調整可以留在 `.drawio` 原生模型；D2 的位置則由來源與佈局引擎決定。不應把 draw.io 拖曳結果承諾成 D2 能往返保存的固定座標。

## 11.5 轉換前先列出會失去什麼

| 從／到 | 可期待保留的部分 | 需要重建或另驗證的部分 |
| --- | --- | --- |
| D2 → draw.io 重建 | 人工映射後的元件與呼叫端點 | 容器模型、座標、樣式、連線綁定、編輯行為 |
| Mermaid → PlantUML 重述 | 已確認的分支和狀態規則 | 參與者、訊息順序、前置條件、狀態轉移細節 |
| Graphviz → 服務架構圖 | 明確有對照的模組概念 | 模組如何部署到服務、外部系統邊界；缺資料時不能推定 |
| Excalidraw → 正式規格 | 已有決策依據的便條內容 | 未定數值、責任人、例外與驗收條件 |
| 任一來源 → SVG／PNG | 該次渲染可見的圖像 | 原生語意、群組、端點綁定與完整編輯能力 |

這是資訊保留風險表，不是本次實測的轉換器支援表。各列不是同一種「轉檔」：有的是重建模型，有的是重新敘述需求。

PNG 可能包含某些工具的嵌入場景資料，SVG 也可能帶可編輯資訊，但必須由確定的匯出選項與實際重開驗證。本書不能只憑「這張圖看得到」就保證裡面有可編輯場景。

若確實要交接轉換，至少交付：來源版本、映射表、丟失資訊清單、轉換後原生檔、預覽、真實編輯與重開的結果。未測的保存流程仍要寫未測。

## 11.6 變更不是全檔搜尋取代

[變更演練單](../../examples/cross-tool/change-drill.md) 假設提出「訂單 API」顯示名稱調整，但不改端點或政策。這是待確認演練，不代表本章已批准或套用改名。

先確認這只是顯示名稱，還是服務真的拆分了。若只是文字變更，優先檢查 D2、draw.io、PlantUML 時序圖的對應標籤，再搜尋說明與提示詞；保留穩定 ID。Graphviz「訂單模組」不因字串相似就自動改成「訂單 API」。

若是查詢上限調整，則首先處理需求與假設。第 6 章的三次上限是教學假設；第 9 章仍把總期限與間隔放在待釐清欄，這不是矛盾。不能為了「一致」把白板改成已確認。真正批准新上限時，要檢查狀態條件、圖例、概念類別基數及文件，而不只是替換一個數字。

若服務拆分，文字更新就不夠：需重新確認容器、呼叫端點、時序參與者及模組映射。既有四邊契約應當因拓撲改變而失敗；不要先修改測試讓它變綠，必須先有新需求作為新契約依據。

## 11.7 不把版本指紋當作語意證明

對照檔保存八份來源的 SHA-256。它們能回答「此張對照表當時檢查了哪份檔案」，不能回答「內容是否符合真實業務」。來源修改後，舊指紋只表示需要重新檢查，不一定表示修改錯誤。

同理，SVG 的自動 ID 或字型字寬可能讓產物雜湊改變，而圖意並未改。版本控制需要同時保留來源差異、契約測試和視覺走查。

## 11.8 練習與參考判斷

1. 有人要求「把所有 payment 合併」。參考：先指出付款模組與外部支付服務的層次差異，要求提供部署或呼叫映射；沒有資料就不合併。
2. D2 與 draw.io 同時刪掉資料庫邊，兩張圖仍相同。參考：與外部明訂的四邊契約比對，而不是只做兩圖互比。
3. 只改 draw.io 節點位置。參考：保留端點綁定並重開檢查，不要求 D2 座標相等，也不需改 Graphviz 的模組資料。
4. 白板的一個問題已解決，另一個仍未定。參考：拆分便條或明示部分決定，不把整張便條當作全部已確認。

## 11.9 本次交付與限制

本章完成來源對照、權威來源表、變更演練、轉換提示詞及一個窄範圍契約測試。故障注入只在暫存副本執行，既有八份來源指紋確認未變。

沒有新增或執行格式轉換器，沒有新圖片，也沒有重跑六套渲染器或 GUI 編輯。本次可證明的是列出的來源引用與四條端點契約，不是全書所有圖語意完全一致。現行核心 CI 已執行本章端點契約；跨平台與完整書籍發布尚未完成，詳見 [驗證狀態導讀](../validation-status.md)。
