# 通稿用語與證據規則

- 章名採「第 N 章：主題」，工具與主題之間用逗號；保留檔名，避免破壞既有連結。
- 原生 ID、命令、版本、錯誤訊息及歷史證據逐字保留，不因繁中用詞或風格而改寫。
- 對一般敘述使用「原生來源」「預覽」「語意」「佈局」「唯讀」等明確用語；API 名稱或選單仍保留實際名稱。
- 需求 ID 是局部引用，不假設不同案例的 R1–R8 共用含義。
- 說明假設適用的章節。虛構需求、反例、演練和待批准變更分別標明。
- 發布結果要附可核對的來源與範圍；避免「完整驗證」「全平台通過」等超出證據的概括。
- 保留歷史的工具／測試結果，現況變更使用導讀補充。不把 API 模型往返改稱 GUI 保存。
- 當一個說明已在基礎章定義，後續簡述差異並交叉引用；不要為增加篇幅反覆宣稱同一個原則。
- 每章提供練習、範圍限制與導覽。練習答案可以是待確認問題，不強迫捏造完整方案。
- 全書通稿與出版驗收分開；排版、讀者試讀、跨平台和授權另設關卡。
