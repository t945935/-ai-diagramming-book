# 共用術語與範圍

本頁統一敘述用語，不重新命名既有原生 ID，也不把不同層次的物件硬合併。教學假設不是生產政策。

| 用語 | 本書意思 | 不應混同 |
| --- | --- | --- |
| 付款／扣款請求 | 對原付款發出的操作；第 6 章每筆訂單最多一次 | 查詢付款結果，不是再扣一次 |
| 明確失敗 | 已取得確定失敗結果，依該案例規格處理 | 逾時、尚未收到結果、付款前取消 |
| 結果未知／待確認 | 未知描述觀察結果；待確認是圖中的狀態或處理標籤 | 不代表已失敗或可立即釋放占用 |
| 庫存預留 | 訂單流程為商品保留的數量／資源 | 退款額度占用；兩者不是同一種帳務 |
| 退款額度占用 | 第 13 章處理中或未知退款所占的可退金額 | 已成功退款金額 |
| 支付服務／外部支付服務 | D2、draw.io 與 PlantUML 中的外部服務角色 | Graphviz 的 payment 付款模組 |
| 呼叫端點契約 | 本書選定的 D2／draw.io 四條關係與映射 | 完整標籤、容器、樣式或語意等價 |
| 模組依賴 | consumer → dependency；影響範圍反向追蹤 | 處理流程、時間順序或故障必然傳播 |
| 原生來源 | 本案例實際維護的模型或文字檔 | 任意可見圖片；生成 DOT 也未必最上游 |
| 模型重新載入 | 序列化後再讀入編輯器模型 | 原生系統保存對話框測試 |
| 瀏覽器儲存重載 | 網頁從瀏覽器暫存恢復場景 | 下載修改檔後重新開啟或永久備份 |
| 渲染通過 | 指定環境能產生有效產物 | 業務、視覺、GUI 或安全稽核全通過 |
| 核心測試 | 目前 Makefile check-core 的六個方法 | 完整現有十個測試或所有工具測試 |

需求 ID（例如 R8）以範例目錄為範圍；跨章引用請附來源。paymentKey 與退款鍵表示不同操作，不可為了用語統一而替換原生識別碼。

## 不能自動全書套用的假設

- 第 4 章：庫存預留與建單協調由下層保證；對帳只畫交接，不定期限。
- 第 6 章：最多三次自動查詢是本例上限，不是供應商標準；只查詢、不重扣。
- 第 9 章：「已確認」僅指白板的虛構前提；待釐清問題沒有因此獲得數值或責任人。
- 第 13 章：整數新臺幣元、固定退款鍵及供應商冪等支援是本例前提；不是通用金額或已整合支付服務。
